你需要为《阿瓦隆（Avalon）》多人在线游戏设计一套完整的“游戏结算 + 断线处理 + AI接管机制”的系统设计文档。

该系统运行在多人实时对局环境（WebSocket或类似长连接架构），后端推荐使用Rust（tokio），需要考虑状态一致性与并发安全。

========================
一、需求目标
========================

实现以下核心功能：

1. 游戏结束后：
   - 弹出“结算页面（Victory/Defeat）”
   - 显示：
     - 胜利阵营（好人/坏人）
     - 每个玩家的角色
     - 刺杀结果（如有）
   - 所有玩家必须点击“确认”才能返回房间

2. 游戏中限制：
   - 游戏进行中禁止玩家主动“退出房间”
   - 仅允许断线（非主动退出）

3. 掉线机制：
   - 玩家掉线 → 标记为“离线状态”
   - UI提示：某玩家离线
   - 若玩家在 60 秒内未重连：
       → 由 AI 接管该玩家
   - 掉线用户重新连接进入房间的提示(重新上线后可重新进入房间或不进入)

4. AI接管规则：
   - 接管后立即参与游戏（投票/任务等）
   - 使用与玩家相同角色
   - 使用标准AI策略

5. 游戏结束后：
   - 被AI接管的玩家：
       → 自动移出房间（或标记为离开）
   - 正常玩家：
       → 点击确认后回到房间

========================
二、系统模块设计
========================

请设计以下模块：

1. Room（房间管理）
2. GameState（游戏状态机）
3. PlayerState（玩家状态）
4. ConnectionManager（连接管理）
5. AIManager（AI接管模块）
6. SettlementManager（结算模块）

========================
三、核心数据结构（Rust风格）
========================

必须包含：

enum PlayerStatus {
    Online,
    Offline { since: Timestamp },
    AIControlled,
}

struct Player {
    id: PlayerId,
    role: Role,
    status: PlayerStatus,
    connection_id: Option<ConnId>,
}

struct Game {
    id: GameId,
    state: GameState,
    players: Vec<Player>,
    phase: Phase,
}

========================
四、游戏流程设计（重点）
========================

1. 游戏进行中：
   - 禁止调用 leave_room()
   - 若调用 → 返回错误（Forbidden）

2. 掉线流程：
   - on_disconnect(player_id):
       → 标记为 Offline
       → 记录时间戳
       → 广播“玩家离线”

3. 重连流程：
   - on_reconnect(player_id):
       → 恢复 Online
       → 恢复控制权（若未被AI接管）

4. 超时处理（关键）：
   - 定时任务扫描 Offline 玩家：
       if now - offline_time > 60s:
           → 转为 AIControlled
           → 启动AI逻辑

5. AI接管后：
   - 玩家行为全部由AI执行
   - 记录日志（用于结算展示）

========================
五、结算页面设计
========================

1. 触发条件：
   - 游戏胜负已确定

2. 状态切换：
   GameState → Settlement

3. 展示内容：
   - 胜利阵营
   - 所有玩家角色
   - 刺杀信息
   - 每轮任务结果

4. 玩家交互：
   - 每个玩家点击“确认”
   - 记录 ready_to_exit = true

5. 返回房间条件：
   - 所有玩家确认 OR 超时（如30秒）

========================
六、AI玩家退出机制
========================

游戏结束后：

for player in players:
    if player.status == AIControlled:
        remove_from_room(player)

========================
七、并发与一致性要求
========================

必须考虑：

1. WebSocket断线重连一致性
2. 状态机原子切换（避免重复结算）
3. AI接管与玩家重连冲突：
   - 若AI已接管 → 玩家不能恢复控制

========================
八、异常情况处理
========================

1. 多人同时掉线
2. 玩家在结算阶段断线
3. AI接管瞬间玩家重连
4. 房主掉线

   - 结算逻辑
6. 前后端交互接口设计（API/WebSocket事件）

代码要求：
